# 切块规则

入库切块的实现在 `server/src/citekit_server/kb/chunking.py`，由 `kb/process.py` 在解析正文之后调用。文档里的「大小」一律指 **Python 字符数**，不是 token。

已入库的数据不会因为改了切块代码自动更新，需要重新处理才会按新规则切片。

单测：`server/tests/test_chunking.py`（在 `server` 目录下 `PYTHONPATH=src .venv/bin/python -m unittest tests.test_chunking`）。

---

## 两层结构

| 层 | 存什么 | 干什么 |
| --- | --- | --- |
| 父块 | MySQL `chunks` 全文 | 检索命中后交给模型读的完整段落 |
| 子块 | 只进 Qdrant 向量，payload 带父块 `chunk_id` | 用来被搜到；命中后仍返回父块 |

默认策略（`chunkSettingMode = auto`）**不切子块**。检索向量就是父块本身。

自定义分块由 **`useChildIndex`** 控制是否切子块。新选自定义时默认打开。旧配置没有该字段时也视为打开。问答对提取没有子块。

---

## 先要不要切

`should_split`：

- **问答对**：一定切（先按窗口切开再抽 QA）
- **强制分块**：一定切
- **原文长度大于模型上下文 70%**：超过才切，否则整篇一块
- **原文长度大于 N 字**（默认 100）：不够长则整篇一块

切之前会 `_prepare_text`：行尾没有句号等标志的换行，可能被粘成一行（PDF 断行）。这和策略无关，三种切法都会先经过这一步。

---

## 父块：三种策略

入口 `split_parents`。共用「要不要切」和问答对滑窗。之后三种策略分开走，不再共用一条「先切再拼满」的流水线。

`chunkSettingMode = auto` 时，即使配置里还留着 `chunkSplitMode = char/size`，也强制走 **按段落**。

### 1. 按段落（默认，以及自定义「按段落分块」）

`_split_by_paragraph`

1. 若有模型识别出的段落列表（仅自定义 + 按段落 + 开启模型识别时），用模型结果。
2. 否则在标题处断开。标题包括 Markdown `#`、Word 标题样式转成的 `#`、`第X章/编/部分`、`第X节`、`第X条`、短的 `1.1` / `1、` / `一、` 等。深度由「最大段落深度」控制（默认 5）。只有标题、没有正文的行会并入下一段正文。
3. 识别不到标题：按空行分段；仍只有一段再按换行切。

然后：

- **有标题或模型段落**：每一段单独成父块。某段超过「最大分块大小」时，再按句子切开（见下方「超长再切」）。`chunkSize = 0` 表示不限制，不再按字数拆。
- **没有标题**：空行/换行得到的短段会贪心装进同一父块，直到接近 `chunkSize`。这是唯一还会「短段拼满字数」的父块路径。

相邻标题段 **不会** 为了凑满 1000 字而合并。

### 2. 按长度（自定义「按长度分块」）

`_split_by_size` → `_window`

整篇按 `chunkSize` 切开（默认至少 1000；界面上 0 会纠正成 1000）。尽量先按句界切再装进这个长度；装不满句界时才按字符硬切。

**分块重叠 `chunkOverlap` 只在这里生效**：下一块开头带上上一块末尾，减轻切在句子中间。须 `< chunkSize / 2`，默认 0。切走定长模式时界面会把重叠清零。

按段落、按分隔符、子块都 **不用** 这个重叠。

### 3. 按分隔符（自定义「按指定分隔符分块」）

`_split_by_delimiter`

按所选分隔符切开（`|` 表示多种分隔符；`\n` 表示换行）。每一段单独成父块；超过最大分块大小再按句子切。`chunkSize = 0` 表示不限制。

未填分隔符时后端回退为 **单个换行**，不是整篇一块。界面已去掉「不设置」，空值会落成「1 个换行符」。

---

## 超长再切（句界）

`_split_for_index` / `_window`：

1. 在 `。！？；!?` 和换行后面断开
2. 单段仍超长 → 再按 `，、；;：:` 切开
3. 还超长 → 按目标长度做不重叠硬切（定长父块若设了重叠，硬切会带重叠）

贪心装块：当前块再加下一句会超 → 当前块先封口，下一句成为新块开头。

---

## 子块

`child_indexes`，仅 **自定义 + 分块存储 + 打开生成子块索引**。

要生成子块，还须同时满足：

- 该父块长度 **大于** 索引大小
- 有父块上限时，索引大小 **小于** 父块上限（否则视为没必要切子块）
- 切完之后 **多于 1 条**（只有 1 条就仍用整段父块做向量）

切法与父块策略无关，都是对 **这一段父块正文** 按句界切开，再贪心装到索引大小，**重叠为 0**。

因此：

- 按段落 / 按分隔符的父块通常本身接近整段结构，子块切点多半在句尾；一块子块里往往是若干句，不是一块一句。
- 定长父块可能从句中切开，子块只能在这段残文里找句号；开头、结尾可能是半句。
- 父块没有标点（也没有换行/逗号）且长过索引大小：子块按索引大小硬切，不保证是句子。
- 子块字数 **不会超过** 索引大小（硬切也按这个上限）。

入库：有子块时 Qdrant **只向量化子块**，不再给整段父块单独一条向量。全文检索仍扫父块（含标题、正文、子块/补充索引文本）。语义命中子块后用 `chunk_id` 找回父块；同一父块多条子块命中会合成一条。重排和 MCP/Agent 看到的都是父块全文。

---

## 问答对

`trainingType = qa`：先把原文按窗口切开（窗口默认 `chunkSize` 或 8000），再对每个窗口调模型抽 `{q,a}`。没有父子文档。

---

## 和切块相邻、但不改变切法的选项

这些在 `kb/process.py`，发生在切块前后：

- **将文档标题加入索引**：向量化文本前加上数据集/文件标题，不改分块正文
- **自动生成补充索引**：每块再生成若干问法/关键词，另写向量
- **图片自动索引**：用视觉模型描述图片，拼进正文后再切
- **PDF 增强解析**：用视觉模型把 PDF 页打成 Markdown，再切

## 代码入口

| 函数 | 作用 |
| --- | --- |
| `split_parents` | 父块总入口 |
| `_split_by_paragraph` / `_split_by_size` / `_split_by_delimiter` | 三种父块策略 |
| `_fit_parts` | 一段一块，仅超长再切 |
| `_pack` | 短段贪心装到上限 |
| `child_indexes` | 父块 → 子块 |
| `embed_items`（`kb/process.py`） | 决定向量化父块还是子块 |
| `search_kb`（`retrieve.py`） | 搜子块、回父块 |
